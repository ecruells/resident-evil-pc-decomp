# RE1 Asset Migrator

A portable Qt GUI that migrates the assets this port needs. It replaces the old
`scripts/build_dc_assets.py` importer and adds the base-game migration the script
never handled.

It is a **tool**, not part of the game: `Game.vcxproj` and the root
`CMakeLists.txt` do not reference it, and it builds 64-bit with its own Qt kit
(the game stays 32-bit MSVC).

## Shared options

Two rows above the tabs apply to whichever tab is run:

- **Target game folder** - where `USA/`, `JPN/`, `DC/` and `SATURN/` are
  written.
- **Room backgrounds** - the format the migration leaves its backgrounds
  (`Stage*/RC*.pak`) in:
  - *PAK (original)*: what the PC release ships. Nothing is converted.
  - *WebP lossless*: every `.pak` becomes `RC*.webp` with the same pixels,
    about 20 % smaller (USA tree: stage 3 goes from 7.0 MB to 5.7 MB).
  - *WebP lossy*: smaller again and not exact - about 60 % smaller at the
    default quality 90.

  The conversion is a pass over the finished tree (`core/BackgroundWebp.cpp`),
  after the tab's own verification: each `.pak` is decoded, encoded with
  ffmpeg's `libwebp`, **read back with the game's own decoder** and - for
  lossless - compared pixel for pixel, and only then replaced. A file that is
  not a 320x240 background TIM (the PC release has one, `Stage3/RC3062.PAK`,
  which is 316x236) is left as a `.pak`. The game takes a `.webp` over the
  `.pak` of the same name (`src/game/RoomBackgroundWebp.cpp`,
  `docs/HD_TEXTURES.md`), so the two formats can be mixed between a base tree
  and its overlays.

  With a WebP format the PC tab also runs with **no source at all**: it then
  only converts the backgrounds of the tree that is already in the target.
  Going back to PAK needs a new migration from the source; a PAK run removes
  any `.webp` an earlier run left beside the `.pak` files it writes, since the
  game would otherwise keep showing the old one.

## Tabs

### PC Assets

Migrates a USA or Japanese base tree.

- **Source** is either an already-extracted folder or a disc image
  (`.iso` / `.bin` / `.cue`). From an image the asset folders are read straight
  out of ISO9660; from a folder they are copied.
- **Asset type** picks the destination tree, `<target>/USA` or `<target>/JPN`.
- Folder names are canonicalised on the way in (`DATA` -> `Data`,
  `MOVIE` -> `Movie`, ...), so a retail layout and this repo's tree both work.
- **Convert movies** transcodes every `Movie/*.avi` to `.mp4` (H.264 + AAC)
  with ffmpeg. The engine prefers a `.mp4` sibling and falls back to the `.avi`,
  so keeping the AVI is safe (and the default).

The base tree is only added to; existing files are never deleted.

Every run also writes the **title menu font**, `<tree>/Data/TITLEFNT.BIN`
(2,953 bytes): the PC/PS1 option typeface, A-Z, which the game draws its title
menu with in every mode (NEW GAME / LOAD GAME / EXTRA / OPTIONS). It is **not
read from any disc** - `core/TitleFont.cpp` carries the glyphs
(`core/TitleFontGlyphs.inc`, generated by `tools/gen_title_font.py`: 17 letters
cut from the Director's Cut's option cells and nine drawn by hand). When
`<target>/HD` already exists the run also refreshes the HD fonts,
`HD/<USA|JPN>/Data/TITLEFNT.TTF` and the 8x8 font's `FONTUS.TTF` / `FONT.TTF`
(see HD Pack below).
`re1am_selftest titlefont OUT.BIN` writes the same file on its own. Without it
the game keeps the art the release shipped with and has no OPTIONS item.

**Add PS1 assets from a PS1 disc image** (optional) supplements the same tree
from a 1996 PS1 disc or the Director's Cut, for the PS1 staff and cast rolls in
OG mode (`[Game] Ps1EndingCredits=1`):

- **Ending-credit data** copies `DATA/STAFF.STF`, `STAFF2.STF` and `BIO.TIM`
  into `Data/`. The tree's own `EN05`/`EN07`/`CLIS01`/`JILL01` are kept.
- **Prologue FMV subtitles** decodes the disc's `DATA/JIMAKU00/01/02.RGB` into
  `Data/jimaku00/01/02.png` — 320-wide greyscale images the JPN prologue FMV draws
  (`[Game] Ps1FmvSubtitles=1`, read from the JPN tree). Only the Japanese
  releases carry the files; a disc without them is skipped, not an error. The
  format and the cue tables are documented in `docs/PS1_FMV_SUBTITLES.md`.
- **Convert PS1 movies** turns the disc's `.STR` files into `.mp4` in `Movie/`:
  always `STFC`/`STFJ` (the movies the PS1 credits play), plus any movie the
  tree has no `.avi`/`.mp4` of. Movies are named the way the PC FMV table
  expects (USA: `ED4`->`EU4`, `ED5`->`EU5`, `OJ`->`OU`, `PJ`->`PU`); `STFC`/`STFJ`
  keep their names, since `stfc_r`/`stfj_r` are the PC rolls with the credits
  baked in.
- **Replace the tree's own movies** overwrites those with the PS1 versions
  (and re-converts `STFC`/`STFJ`).
- **PS1 audio** replaces the tree's sound effects, voices and BGM in
  `Sound/` and `Voice/` with the disc's, under the tree's own file names.
  Every name the PS1 has no counterpart for keeps the tree's file. Everything
  written is listed in `Sound/AUDIO.TXT`; that file is also what makes the
  game mix at 44.1 kHz instead of 22.05. No config key: the files are the
  switch. **Running the PC migration again (with a PC source) restores the PC
  release's sounds**: it deletes the listed files first, then copies the
  originals back.
  - *Format*: WAV (lossless, ~525 MB) or Ogg Vorbis (ffmpeg with `libvorbis`,
    quality 0-10, default 6: ~90 MB, transparent for these 4-bit ADPCM
    sources). The game looks for `<name>.ogg` before `<name>.wav`, so an OGG
    run deletes the `.wav` it replaces. Loop points travel as the Vorbis
    comments `LOOPSTART`/`LOOPLENGTH`; the game decodes with the vendored
    `src/third_party/stb_vorbis.c`.
  - *Sound effects* come out of the VAB banks (`SOUND/*.HED`+`.VB` and the
    bank inside every room `.RDT`) at each tone's PS1 playback rate, 16-bit.
  - *Voices* are cut out of `VOICE1-5.XAS`: 16 CD-XA channels interleaved
    sector by sector, 37.8 kHz. **Needs a raw `.bin`/`.cue`**; a 2048-byte
    image cannot carry the XA channels and the voices are skipped. A name
    always gets the clip the PS1 plays at its ids, even where the PC shipped
    different audio under it (15 names). That matters for timing: the DC's
    room 513 waits for voice 0x51 (`VB00_11`) to finish, 10.0 s on the PS1
    but 17.4 s for the PC file, which stalled the scene. Ids whose clip no
    PC name holds get their own `Voice/P<row>_<id>` file, which the game
    plays for that id: an id that shares a name with a different line
    (stage 1 id 0x63, stage 5 id 0xAB) or one whose PC name is empty (stage
    5 ids 0xB5/0xB6).
  - *BGM* is rendered from the `SEPxx.HSB` sequences through an SPU model
    (ADPCM, the hardware interpolation table, ADSR, the Room reverb preset the
    game selects) at 44.1 kHz stereo. A looping track is written as intro +
    loop with a `smpl` loop region, and the game loops only that region, so
    the intro plays once as on the PS1 (the PC build loops the whole file).
  - Levels are matched to the PC files so the PC engine's volume settings
    still balance: SFX through libsd's squared volume law, voices by a
    measured constant, each BGM to its PC file's RMS.
  - Which PS1 sample becomes which PC file is fixed at build time in
    `src/core/Ps1AudioManifest.h`, generated by
    `tools/gen_ps1_audio_manifest.py`: 373 of 418 sound effects, all 517
    voice names plus 4 PS1-only clips, and 82 of 84 BGM channels. The sound
    effects and BGM left out have no PS1 counterpart that matches the PC file
    and keep it. A Director's Cut disc works too;
    its audio is the same except three samples it re-encoded at half rate
    (`drw_opmt`, `drw_shmt`, `slide_bk`), which the log names. The 1996 disc
    gives the full-rate originals.
  - Well under a minute for WAV, about half a minute more for OGG (the
    encodes run in parallel).

With a PS1 image the PC source can be left empty to update an existing tree.
Use a raw `.bin`/`.cue` so the movies' CD-XA audio is intact.

**Weapon gun textures** -> `<tree>/Players/W<nn>_<c>.TIM` (`core/WeaponTextures.cpp`,
`re1am_selftest weapontex TREE` runs it alone). A weapon model has no texture
and samples its holder's page, gun and hand together, so a gun drawn only on
one model's page (the DC's custom Beretta, Jill's flamethrower) is wrong on
every other one. Each file is the default model's left page plus a mask of the
gun's texels - the ones every outfit of that character in the tree leaves
alone. When the worn model's page does not already show that gun, the game
draws the gun's triangles from the file and the hand's from the worn page
(`src/game/WeaponTexture.h`); otherwise nothing changes. Written by this tab for the base tree, and
again by the Director's Cut tab (its own `W0F_0`/`W1F_1`, and the base trees
once they hold the DC outfits) and the Saturn tab (the base trees, with the
Saturn outfits).

### Director's Cut

Builds the `DC/` overlay from a Director's Cut disc image. **An image is
required**, not an extracted folder: a raw 2352-byte `.bin`/`.cue` keeps the
CD-XA audio of the `.STR` movies intact, which a 2048-byte content copy
truncates.

It extracts the disc's asset folders, runs every overlay step (arrange rooms,
rooms, models, Data, title art, item sprites/models, the save-screen font CLUT
rows, the PS1 colour-key -> PC index-0 transparency relabel, and the
STAFF.STF/STAFF2.STF/BIO.TIM ending-credit resources), decodes **every**
`.BSS` background to `.pak` (STAGE1-7 and STAGE8-E), and converts the `.STR`
movies to `.mp4`.

`Base tree` selects which tree the overlay is built on top of (it is only read:
the font comes from it). Movie conversion keeps each STR's original CD-sector
timing by default, at the PS1's 150 sectors per second through the last valid
video sector. `Prologue FMV subtitles` decodes the disc's
`DATA/JIMAKU00/01/02.RGB` into `<target>/JPN/Data/jimaku00/01/02.png` — the
Japanese prologue subtitles (`[Game] Ps1FmvSubtitles=1`). They go into the JPN
tree rather than the overlay, because `Ps1FmvSubtitles` builds its path from the
compile-time `GAME_DATA_ROOT_JPN`, so an overlay
copy would never be read. `Verify` runs
the coverage and background checks afterwards.

The other files written outside `<target>/DC` are the **bonus outfits**: the
arrange game's player models, copied into the base tree's `Enemy` folder
(`<target>/USA` and/or `<target>/JPN`, whichever exists) as `EM1052.EMD`
(Chris, the disc's `EM1032`), `EM1053.EMD` (Jill, `EM1033`) and `EM1055.EMD`
(Rebecca, `EM1035`). The game offers them as outfits in every mode once the
arrange game is cleared (`src/game/Bonus.h`); the disc's own names are the PC's
alternate outfits', so the copies take names no release uses.

### Sega Saturn

Builds the `SATURN/` overlay from a Resident Evil **Sega Saturn** disc image
(the track-1 `.bin`, or the `.cue`; track 1 is `MODE1/2352` ISO9660). Only what
the Saturn release adds is written; everything else falls back to the base
tree, which is never written to.

**The Japanese disc ("Bio Hazard")** - often a cooked `MODE1/2048` `.iso` - is
detected from its `GAME5.PRG` (where the wardrobe questions sit,
`saturnRegionFromGame5`) and written to **`SATURN_JPN/`** instead, which the game
reads in place of `SATURN/` with `[Assets] Version=JPN` (its room text is in the
PC `Biohazard.exe` encoding). Same file set, with three differences: the
wardrobe patch writes the Japanese questions, the results screens copy
`Data/BATTLE.BIN` + `Data/RANKING.PRG` (the Japanese labels and prompts are
inside `BATTLE.BIN`; `RANKING.PRG` carries the rotating "BIO HAZARD" logo
model) - the disc has no `WAPON3.BIN` - and `--all-rooms` decodes the Japanese
rooms. See `docs/SATURN_VERSION_ANALYSIS.md` §6b.
`re1am_selftest saturn <iso> <target>` runs it headlessly;
`re1am_selftest satwardrobe IN OUT jpn` runs the Japanese wardrobe patch alone.

Everything below up to "Optional" is **always migrated** - the port's Saturn mode
needs all of it, so there is no switch. The tab offers the optional
migrations listed further down (all models; all rooms and backgrounds; all
campaign BGM; the FMV) and the audio format and quality, which apply to every
rendered sound.

- **Saturn-only creatures** -> `SATURN/Enemy/`: `EM1016`/`EM1116` (the Tick,
  Chris's / Jill's model-table block) and `EM1017`/`EM1117` (Zombie Wesker),
  converted to PC `.EMD`s by `core/SaturnEmd.cpp`, a port of
  `tools/saturn_emd.py pc`. The mesh and textures are the Saturn's; the
  animations are the PS1 data every Saturn EMD carries (the Hunter's / the
  zombie's). The textures take 4-5 pages, which the game reads through
  `PSXObject_SetTexHeight` (these models only).
- **Saturn alternate outfits** -> `SATURN/Enemy/`: the disc's `EM1030`/`EM1032`
  (Chris) and `EM1031`/`EM1033` (Jill), written as `EM1060`/`EM1061` and
  `EM1160`/`EM1161`. The Saturn gives its outfits the very names the PC and the
  Director's Cut give theirs (those files are different models), so they are
  **renamed** and the port picks them by model-table index - Chris/Jill block
  slots 28 and 29 - never by name, which is what keeps them from shadowing the OG
  and DC outfits. The player models carry 23 meshes against the PS1 skeleton's 15
  joints; the converter takes the 15 the skeleton reaches.
  Weapon models have no texture of their own and sample the holder's left page,
  which is the PS1 original's. The DC's custom Beretta (`DC/Players/W0F.EMW`,
  `W1F.EMW`) reaches texels only the DC's own `CHAR10`/`CHAR11` have its art
  in, so when `<target>/DC` exists those texels are copied from there (without
  it the gun shows the PS1 filler, yellow on Jill's). **Migrate the Director's
  Cut before this disc.** With the weapon gun textures (PC tab) the game draws
  the custom Beretta and Jill's flamethrower from those instead, on any outfit;
  once the base tree has `W15_1.TIM` this tab no longer writes the patched
  `SATURN/Players/W15.EMW` (and removes an old one), which would hide it.
- **Battle Game arenas** -> `SATURN/Stage8/`: the 15 `STAGE8/ROOM80x0.RDT`,
  LZ77-decoded (`core/SaturnLz77.cpp`) into ordinary PS1 RDTs, with the PS1
  colour-key -> PC index-0 transparency relabel. The arenas reuse campaign
  backgrounds, so no `.BSS` is converted.
- **Laboratory Tyrant room** -> `SATURN/Stage5/`: `RC5130..5137.pak` (background)
  and `ROOM5130.RDT` + `ROOM5131.RDT` (room data; each decoded from its own disc
  file, Chris and Jill differ). The
  Saturn re-cut this room's **art and its data**: the PC's init script is 28
  bytes — one `item_model_set` record — longer, and its `item_icons` table holds
  two 40x30 icons against the Saturn's one, i.e. a pickable item (the magazine
  clip) the Saturn does not have. Loading the Saturn's room removes it without
  any engine change. The room *file's* object models are byte-identical on the
  two sides, but the Saturn does not draw them: it loads one `ENEMY/OBnn.DAT`
  per object slot. For this room slot 0 is `OB80.DAT`, the dark cover over the
  second capsule, which `core/SaturnObModel.cpp` converts (LZ77 MBN mesh + the
  Saturn's hardcoded per-model transform) into a PC TMD + flat TIM, appended to
  the written `ROOM5130.RDT` with `object_models[0]` pointed at it.
  Only rooms the Saturn actually re-cut are copied; the other 107 differing
  background frames are other rooms' re-dresses and stay on the base tree.
- **Wardrobe** -> `SATURN/Stage1/ROOM11C0.RDT`, `ROOM11C1.RDT` and
  `SATURN/Stage6/ROOM61C0.RDT`, `ROOM61C1.RDT`: the Saturn's rooms, decoded,
  relabelled and **patched** (`core/SaturnWardrobe.cpp`). On the Saturn the two
  extra outfits are offered by GAME5 code, not by the room script; the patch
  writes that as SCD (area 4 -> event 0, outfit 2; area 5 -> a new event 3,
  outfit 1; the Saturn's three questions as room messages 3-5), so the port needs
  no wardrobe code. The new message and event tables go in at the VAB body and
  every later offset moves. `re1am_selftest satwardrobe IN OUT` runs the patch
  alone; `tools/saturn_wardrobe_rdt.py` is the byte-identical reference.
- **Bonus outfit** -> `<USA|JPN>/Enemy/EM1061.EMD`, `EM1161.EMD`: copies of the
  converted Saturn-exclusive outfit in the **base** tree (whichever of the two
  trees exists), because the game offers it as a bonus outfit in every mode once
  it is unlocked (`src/game/Bonus.h`). The names are already ones no other
  release uses.
- The **title menu font** is no longer written here. It is the PC tab's
  (`<tree>/Data/TITLEFNT.BIN`), since every mode draws its title menu with it;
  a `SATURN/Data/TITLEFNT.BIN` from an earlier migration is still read.
- **Battle Game music** -> `SATURN/Sound/`: `Bgm_58` (the arena loop,
  `SND/BATTLE.CDP` song 0), `Bgm_59` (the end-of-run fanfare, song 1),
  `Bgm_24` (`BGM34B.CDP` song 2, arena 15), and `Bgm_5a`
  (`SND/NAME.CDP`, the ranking screen), WAV or Ogg Vorbis (ffmpeg with
  `libvorbis`), levelled to the PC BGM's median RMS. The Saturn's
  music is sequenced: `core/SaturnSound.cpp` plays it through a model of
  Sega's sound driver (the sequencer, key-on and pitch tables read out of the
  disc's own `SND/SDDRVS.PCK`) and of the SCSP, reverb included (MAME's
  `scsp.cpp`/`scspdsp.cpp` behaviour; see `THIRD_PARTY_NOTICES.txt`). Loop regions and the marker go in as
  for the PS1 audio (`core/AudioWriter.cpp`), and `Sound/AUDIO.TXT` makes
  the game mix at 44.1 kHz. The other arenas reuse campaign music the base
  tree already has. Format and checks: `docs/SATURN_VERSION_ANALYSIS.md` §6a.
- **Tick sound effects** -> `SATURN/Sound/Tk_*` (`SND/SE308.CDP`).
- `SATURN/SATURN.TXT` lists what was written.

Optional (off by default):

- **All enemy and character models** -> `SATURN/Enemy/`: every other
  `ENEMY/*.EMD` on the disc - the enemies and NPCs (`EM10xx`/`EM11xx`) and the
  four player models (`CHAR10..13`), 63 files - converted like the
  creatures above and written under the disc's names, which are the PC's, so
  Saturn mode draws the Saturn's meshes for everyone
  (`re1am_selftest saturn ... --all-models`). The disc's `EM1030..EM1033` are
  left out: they are the Saturn outfits, already written as `EM106x`/`EM116x`,
  and under their disc names they would shadow the PC's own outfits. About 19 MB;
  a converted model is 1.5-2.5x the PC file (up to 478 KB), which the game's
  `DATA_BUFFER_PORT_HEADROOM` and the player buffer's `spillGuard` are there for.

What `core/SaturnEmd.cpp` does beyond the plain mesh/texture conversion (all of
it applies to the always-migrated models too; `tools/saturn_emd.py` has none of
it):

- **Joint ids.** Three models label their skeleton nodes with ids that are not
  the PS1's: the Neptune (`EM100B`) repeats one, the wasp (`EM1007`) rotates
  them, the adder (`EM100A`) is rooted at PS1 joint 1. Every node still rests
  where a PS1 joint does, so the ids are taken from the rest positions.
- **Joint offsets.** The Saturn's skeleton is its own (Barry's chest and
  shoulders, Rebecca, Zombie Wesker over the zombie's skeleton, the spider
  web): the node offsets are written into the PS1 skeleton the engine animates
  with (the one at directory dword 1), relative to each joint's PS1 parent.
  Rebecca's root mesh is centred 451 units above the PS1's waist origin; the
  root mesh and its children take that back. **Not covered:** a
  `Players/W??.EMW` carries its own copy of the skeleton for the aim
  animations, which the migrator does not touch.
- **Node scale.** A non-root node's scale is baked into its mesh and its
  children's offsets (the Neptune's dorsal fin is stored at half size under a
  x2 node; Enrico, `EM1028`, has torso and legs at x0.935). The root's scale
  (the Black Tiger's 0.1) and the node angles (`CHAR10`'s feet, the Yawn) are
  not applied.
- **Plant 42's roots** (`EM100E`) are half a root ball on both releases, the
  half the room's camera sees - facing +X on the PS1 and -Z on the Saturn. A
  single-mesh model is turned about Y in quarter turns to fit the PS1 mesh's
  footprint.
- **Joints with no Saturn mesh** (`EM1029`: 4, 5, 7, 8) keep their slot as an
  empty PS1 placeholder.
- **PS1 objects past the Saturn skeleton** keep the PS1 geometry: the Tyrant's
  heart (object 15), Plant 42's bulb and vines (16, 17), the spiders' object
  20. Their texture is the PS1 page, written as **page 0** of the output TIM
  with its colours quantized onto the CLUT entries the Saturn palettes leave
  free; the Saturn textures then start at page 1. The 8-vertex box the player
  and NPC models carry as object 15 stays empty.
- **Models that hold a weapon** - the player (`CHAR10..13`, the outfits) and
  the NPCs (`EM102x`); `re1am_selftest satemd IN OUT weapon` - keep the PS1
  texture's whole left 128x256 page the same way: a weapon model
  (`Players/W??.EMW`, `Players/WS2??.TMD`) has no texture of its own, it
  samples that page of its holder's TIM.
- **Jill's flamethrower** (a port fix, not Saturn data). `Players/W15.EMW` is
  Chris's model - its packets are `W05.EMW`'s - and the flamethrower's texels
  exist in Chris's page only, so on Jill it is textured with her forearm and
  hair, in the PC release too. Her page cannot be patched in place (her other
  weapons use the same texels), so the texels the weapon covers are copied
  from Chris's page (the disc's `CHAR10.EMD`) into the **right half** of page 0
  of Jill's models (`CHAR11`, `EM1160`, `EM1161`), which a weapon holder's
  page leaves empty, and with *All enemy and character models* the overlay
  gets a `SATURN/Players/W15.EMW` - the base tree's file
  (`<target>/USA|JPN/Players/W15.EMW`) with every packet moved 128 texels
  right. No base file, no change. The patched weapon only makes sense over a
  converted Jill, which is why it is written with that option only.

The game reads the page of a packet in two places: `PSXObject_Store`
(`PSXObject_SetTexHeight`) and the per-triangle path Plant 42 and its roots are
drawn through (`TmdAnimation.cpp`), which is what the roots' 8-page texture
needs.

- **All rooms and backgrounds** -> `SATURN/Stage1..7/`: every
  `STAGEn/ROOMsRRv.RDT` LZ77-decoded (no relabel: the shared rooms decode to the
  PC's own bytes) and every `ROOMsRR.BSS` converted to `RC*.pak`, once for both
  character variants. 346 room files and 639 backgrounds, ~450 MB, about 90 s;
  the Laboratory Tyrant room and the wardrobe keep their patched copies, and the scrapped heliport's
  placeholder `ROOM311.BSS` (not a container) is skipped and logged. With it
  Saturn mode runs the Saturn's room data and its (slightly dimmer, sometimes
  re-drawn) art everywhere. The decoded rooms get the same PS1 colour-key ->
  index-0 transparency relabel as the arenas (3.2 M texels). **141 of the 348
  rooms are not byte-identical to the PC's own `.RDT`** (84 at the same size,
  mostly by 1-2 script bytes such as `255 -> 8`; 57 by a few dozen to a few
  hundred bytes of length): the PC release patched their scripts, and this option
  reverts those rooms to the Saturn's unpatched data. (Measured against
  `assets/USA`; Capcom's own PC relabel agrees with ours in 93 TIM blocks, leaves
  60 that ours moves, and the rest of the differences are the script patches.)
- **All room BGM** -> `SATURN/Sound/<PC name>`: every `Bgm_*` the game's
  `g_BgmNameTable` names, rendered from `SND/BGM<group>.CDP` (the Saturn's pack
  is the PC's BGM group, song *k* its channel *k*; `core/SaturnBgmTable.h`,
  generated by `tools/gen_saturn_bgm_table.py`). Needs no code change: the game
  asks for the PC's names and the overlay answers first.
- **FMV** -> `SATURN/Movie/<PC name>.mp4` (H.264 + AAC, needs ffmpeg;
  `core/SaturnMovie.cpp`). `MOVIE.CPK` is 28 Sega FILM 1.06 files (Cinepak
  320x224, 15 fps) end to end, each on a sector boundary; every FILM header
  gives its own length, and the chain covers the file exactly on both discs.
  Same order on both; the PC names come from the port's FMV table
  (`OU`/`OJ`, `EU4`/`ED4`, `stfc_r`/`stfc_b`, ...). The prologue is three
  Saturn files (movies 2, 3, 4) joined into one `PU`/`PJ.mp4`: movie 3 is the
  beat the PS1 drops for Jill, and the game cuts the joined file at the
  Saturn's frame counts (`kSaturnPrologueCut` in `src/video/VideoPlayback.cpp`;
  USA 2430 + 150, JPN 2666 + 151 - the migrator warns if a disc differs). The
  Saturn has no `staf_r` and no PS1-form subtitles or credits text
  (`JIMAKU*.RGB`, `STAFF*.STF`): the Japanese prologue has its subtitles in the
  picture, the staff rolls their credits, and the game does not draw the PS1
  subtitles over a Saturn movie. `re1am_selftest satcpk <image>` prints the
  chain.

Diagnostics: `re1am_selftest satsong <SDDRVS.PCK> <music.CDP> <song|all>
<out.wav|outdir> [--dry]` renders any song of any Saturn music pack
(peak-normalised; `--dry` switches the DSP effect returns off), `satkeys` prints
a song's key-on register images for comparison with a live SCSP dump, and
`satcdp` dumps a pack's segment table and bank headers.
`python tools/saturn_snd.py` lists the same packs, voices and events.
`re1am_selftest audioatomic` checks that a failed conversion leaves the prior
WAV/Ogg files intact; CTest runs this with the synthetic CD_PACK/tone/sequence
parser tests.

Not migrated yet (logged): the rest of the Saturn audio (its SE banks, the
`.PCK` room PCM, the unclassified `X68 SSCONV`
banks), the `BM60` title/ending art and the
`ENEMY/A_*.DAT` room props (the extra lab Tyrant capsule's own billboard - the
fight and the room's art are ported, the capsule model is not). The Battle Game
uses `[Game] Mode=SATURN`, which selects this overlay in the game port.

### HD Pack

Imports a Classic REbirth texture pack - the **Seamless HD Project**, made for the Japanese PC release - into `<target>/HD`,
where the game replaces textures by file name or by content hash
(`docs/HD_TEXTURES.md`). What the table covers is saved under the game file's
own path in `HD/<USA|JPN>/` (`Stage1/RC1060.webp`, `Objspr/OSP01060.webp`,
`Enemy/EM1010.webp`); what is matched against the dump is saved under the
file name the game dumped the same pixels under; the models inside the room
files go to one shared folder, named by their TIM (`HD/USA/RoomModels/<crc>.webp`), or, when the game has no name for it, under
its hash in `HD/` itself (`HD/<hash>.webp`). The pack's own
folders (`bgd`, `mask`, `misc`, `skin`, `skin2`) are not recreated; what an
earlier version left in `HD/<pack folder>/` is moved up into `HD/` first.
An original-game import also writes the HD fonts (`core/HdFonts.h`), both by
Omnibus-Type under the SIL Open Font License 1.1 and embedded unmodified from
`fonts/` by `tools/gen_hd_fonts.py`: `HD/<USA|JPN>/Data/TITLEFNT.TTF`
(Archivo Black: the title menu, PRESS START, the Director's Cut's
STANDARD / TRAINING / ADVANCED) and `HD/USA/Data/FONTUS.TTF` -
`HD/JPN/Data/FONT.TTF` on a Japanese tree - (Archivo Narrow SemiBold: the 8x8
font of the OPTIONS pages and the debug menu, and the title's copyright line),
and the 8x14 game text's `FONTUS_14.TTF` - `FONT_14.TTF` on a Japanese tree -
(subsets of Libertinus Serif SemiBold / M PLUS 2 SemiBold).
With HD textures on the game draws that text in them at the screen's
resolution, and keeps its pixel fonts otherwise; any TrueType font can take
either place. The import deletes the `TITLEFNT.VEC` outlines an earlier
version wrote there. `re1am_selftest hdfonts TARGET [jpn]` writes the fonts on
their own.

- **Pack is for** says which game the selected folder is for: **Original
  game** (a pack's `hires`) or **Director's Cut** (the Seamless HD Project's
  `bio1dc\hires`, the Director's Cut camera angles). Import each folder with
  its own choice.
- **hires folder** is that folder: it holds one or more of `bgd`, `mask`,
  `misc`, `skin` and `skin2`. Nothing else is searched.
- **Names from tree** is the migrated tree (`USA` or `JPN`) the names are
  computed from, original game only. Migrate the PC assets first; for the
  Director's Cut, run the Director's Cut tab first (the names come from `DC/`).
- **ffmpeg** joins a model's two palette pictures and cuts a texture out of a
  pack picture that holds it inside a 256x256 page; it needs `libwebp`.
- **HD movie folder** (optional) is the Seamless HD Project's `movie` folder.
  Its `.mp4` files are copied as they are into `<target>/HD/<USA|JPN>/Movie`
  under the tree's FMV names - the pack uses the Japanese names, so for USA
  `OJ`/`PJ` become `OU`/`PU`, `Ed4`/`Ed5` become `EU4`/`EU5` and the
  `*_B` staff rolls become `*_R` (the pack's roll ends on the RESIDENT EVIL
  logo, so it suits both trees). With HD textures on (`[Textures]
  HdTextures=1`, the default) the game plays `HD/<TREE>/MOVIE/<name>.mp4` in
  place of the tree's own movie; the tree is not touched. **Capcom logo
  movie** and **Shark movie (DM7)** pick a cut from `Capcom clips/` and
  `DM7 clips/`; the main folder holds the Original cut of both. Leave the
  hires folder empty to import only the movies.

The packs name their files with Classic REbirth's hash, so each file is
renamed to the name this game gives that texture (`src/system/HdTextureHash.h`):

1. **Room backgrounds and masks** go by a built-in table of which pack file
   replaces which game file (`core/HdPackTable.inc`, generated by
   `tools/gen_hd_pack_table.py` by comparing the pictures): 605 backgrounds
   and 422 masks, with no need to run the game (a 128x128 mask is cut out of
   the top-left quarter of the pack's 256x256 page). Each is saved as
   `HD/<USA|JPN>/Stage<n>/RC<...>.webp` / `HD/<USA|JPN>/Objspr/OSP<...>.webp`,
   the game file's own path; a copy an earlier import wrote under the
   texture's hash is removed.
2. **Character and enemy skins** go by the same table. The packs carry one
   picture per palette of a model's texture; the port draws a model from one
   picture named after its `.EMD` (the left half in palette 0, the right half
   in palette 1), so the import joins the two halves with ffmpeg (lossless
   WebP) and writes `HD/<USA|JPN>/Enemy/EM1010.webp`. Seamless HD Project gives
   49 models, RE-ENHANCE 34; a model the pack has only one palette of is left
   out.
3. **File textures** - what the game builds straight from one file: `Data/`
   (status screen, font, title and option screens), `Item_m2/` (maps, item
   views), `Item_m1/` (doors) and `Effspr/` (the effect pages the weapon
   flashes, smoke, fire and blood are cut from) - go by the same table, as
   `HD/<USA|JPN>/<folder>/<FILE>.webp` (a 256x256 page picture holding a
   smaller texture is cropped to it, losslessly). Seamless HD Project: 131.
   `Players/` has nothing of its own: the weapons are drawn with the
   character's skin (the gun textures, PC tab, have no HD picture).
4. **Director's Cut** (*Pack is for: Director's Cut*, the Seamless HD
   Project's `bio1dc\hires`): paired with the DC overlay's own files and
   installed under `HD/DC/`: backgrounds as `Stage<n>/RC....webp`, the arrange
   rooms' masks - which the room file carries - as
   `Stage<n>/ROOM...._MASK<camera>.webp`. Run the Director's Cut tab first.
   There is no HD pack for the Saturn release.
5. **Everything else** - doors, menus, items, effects, room objects, and the
   backgrounds and masks the table lacks - is matched against the game's own
   texture dump. Set `[Textures] DumpTextures=1`, play through what you want
   replaced, then run the import: each texture in `<target>/HD/dump` that a
   pack picture shows gets that picture. Run it again after dumping more.

Notes:

- Only confident matches are imported; the log counts, per folder, how many of
  the pack's files went in.
- The names of what came from the dump depend on the pixels the game loads, so
  they follow the **Room backgrounds** format: after converting a tree to (or
  from) lossy WebP, run the import again. The table's files are named after
  the game's files and are not affected.
- A file already in `HD/` under the same name (from an earlier import, in any
  folder) is replaced by the new one. Nothing in the tree is changed; to remove
  a pack, delete its folders in `HD/`.

## Requirements

- Qt 6.8 (MSVC 2022 64-bit kit; `C:\Qt\6.8.3\msvc2022_64` by default).
- Visual Studio 2022/2026 with the C++ toolset.
- `ffmpeg` on `PATH` (or browsed to) for the movie conversions, the Ogg
  audio and the WebP backgrounds (it needs `libvorbis` / `libwebp`, which the
  common builds have).

## Build

```powershell
powershell -ExecutionPolicy Bypass -File tools/asset_migrator/build.ps1
```

or by hand:

```
cmake -S tools/asset_migrator -B tools/asset_migrator/build `
      -G "Visual Studio 18 2026" -A x64 `
      -DCMAKE_PREFIX_PATH=C:/Qt/6.8.3/msvc2022_64
cmake --build tools/asset_migrator/build --config Release
```

`build.ps1` picks the Visual Studio generator from cmake's own default instead
of naming one, so it works on both a VS 2022 and a VS 2026 machine; pass
`-Generator` to override (`-Generator Ninja` also works, from a shell with the
MSVC environment loaded). The Visual Studio generators are multi-config, so
`build.ps1` writes `tools/asset_migrator/build/Release/re1_asset_migrator.exe`;
a single-config generator writes it at the root of the build directory.

## Package a portable folder

```powershell
powershell -ExecutionPolicy Bypass -File tools/asset_migrator/build.ps1 -Package
```

This also runs `windeployqt` and copies the exe, the Qt DLLs and the platform
plugin into `tools/asset_migrator/dist/re1_asset_migrator/`, which runs on a
machine with no Qt installed. `ffmpeg.exe` is not bundled.

## Releases (CI)

`.github/workflows/release.yml` has a `build-asset-migrator` job that installs Qt
6.8.3 (`jurplel/install-qt-action`), builds the tool with Ninja on the runner's
MSVC toolset (`ilammy/msvc-dev-cmd`), deploys the Qt runtime and publishes
`asset-migrator-<version>-windows-x64.zip` as its own release asset (next to the
game's `residentevil-<version>-windows-x86.zip` and the Linux bundle). It runs on
every push to `main` as a compile check, and attaches the zip to the GitHub
release when release-please cuts one. ffmpeg is not bundled, so players need it
on `PATH` (or browsed to) for the movie conversions.

A second job, `build-asset-migrator-linux`, builds the same sources on
`ubuntu-22.04` against the aqt `linux_gcc_64` Qt 6.8.3 kit, runs
`re1am_selftest selftest`, and packs the GUI as an AppImage with
`linuxdeploy` + `linuxdeploy-plugin-qt` (Qt libraries and the xcb platform
plugin bundled). It publishes `asset-migrator-<version>-linux-x86_64.tar.gz`:
the AppImage, `re1am_selftest`, this README and the licences. 22.04 rather than
the game's 24.04 reference image keeps the glibc floor at 2.35. ffmpeg is not
bundled here either.

The Windows job pins no Visual Studio generator: the generator name depends on which
Visual Studio the runner image ships (17 for VS 2022, 18 for VS 2026) and CMake
resolves the instance through its own probe, which is what broke when the image
moved. Ninja needs no such probe.

## Headless verification

`re1am_selftest.exe` (built alongside the GUI) exercises the core without Qt:

```
re1am_selftest info <image> [filter]
re1am_selftest bss <image> <path-in-image> <outdir>
re1am_selftest strinfo <image> [filter]
re1am_selftest jimaku <image> <outdir>
re1am_selftest pc <source|-> <target> <USA|JPN> [--image] [--movies]
               [--ps1 <image>] [--no-ps1-credits] [--no-ps1-subs]
               [--no-ps1-movies] [--ps1-replace] [--ps1-audio] [--ps1-ogg]
               [--ffmpeg <path>] [--webp | --webp-q N]
re1am_selftest dc <image> <target> <USA|JPN> [--no-bg] [--no-movies]
               [--no-subs] [--no-verify] [--ffmpeg <path>]
               [--webp | --webp-q N]
re1am_selftest bgwebp <tree> [--webp | --webp-q N | --pak] [--ffmpeg <path>]
re1am_selftest bgwebp <tree> check
re1am_selftest hdpack <hires folder> <target> [USA|JPN] [--dc] [--ffmpeg <path>]
re1am_selftest hdmovies <movie folder> <target> [USA|JPN]
               [--capcom cubes|original] [--dm7 jill|original]
re1am_selftest ps1audio <image> <tree> [--no-sfx] [--no-voices] [--no-bgm]
               [--ogg] [--ogg-q N] [--ffmpeg <path>]
re1am_selftest bgm <image> <BGM name> <out.wav>
re1am_selftest saturn <image> <target> [--all-rooms] [--all-bgm] [--movies]
               [--ogg] [--ogg-q N] [--ffmpeg <path>] [--no-verify]
               [--webp | --webp-q N]
re1am_selftest satcpk <image>
re1am_selftest satemd <saturn.EMD> <out.EMD>
```

`--webp` leaves the backgrounds as lossless WebP and `--webp-q N` as lossy at
quality N. `bgwebp <tree>` runs only that pass on an existing tree (lossless
by default) and `bgwebp <tree> check` decodes every `Stage*/*.webp` in it.

The C++ decoders were checked against the Python tools:

- `bss` -> `.pak` output is **byte-identical** to `tools/bss_to_pak.py` for
  every camera of a base-stage `.BSS` (ROOM100: 6/6 files match).
- `jimaku` -> `jimaku00/01/02.png` is **byte-identical** to
  `tools/decode_jimaku.py` for all three planes of the Biohazard DC disc
  (SHA-256 match, 23 / 7 / 5 lines), and writes nothing for a USA disc.
- A full DC overlay build (`--no-bg`) is **byte-identical** to
  `scripts/build_dc_assets.py` for the shared output: 584 files,
  0 differences, and the same 136 relabelled files / 3,372,204 texels.
  The ending-credit step additionally emits `Data/staff.stf`,
  `Data/staff2.stf`, `Data/bio.tim`, `Data/en05.tim`, `Data/en07.tim`,
  `Data/clis01.pix`, and `Data/jill01.pix`.
- The `.STR` demux matches `tools/str_to_video.py` exactly (DM8: 160 frames,
  256x240, v2, 3582 audio groups).
- PS1 audio (`ps1audio`), against the PC release's WAVs: all 957 files are
  well-formed. Level ratios PS1/PC come out at 1.03 (SFX), 0.99 (voices) and
  1.00 (BGM). Every BGM's one-pass length matches its sequence's tick count
  (`Bgm_00`: 60.63 s on both), and the long-term spectra of the renders line
  up with the PC files at zero semitone offset (correlation 0.93-0.98). A 1996
  disc and a Director's Cut disc give byte-identical output except the three
  re-encoded samples noted above.
- The game's loader (`src/system/AudioFile.cpp`, built 32-bit) against an OGG
  run: all 976 files are found through their `.wav` names and decode with the
  WAV render's exact rate, channels, length and loop points; the PC's own
  `BGM_33.WAV` reports no loop. Typical Vorbis q6 waveform SNR is ~27 dB,
  sample-aligned.
- The Saturn EMD converter (`satemd`) against `tools/saturn_emd.py pc`:
  **byte-identical for all 46 Saturn EMDs the converter accepts**; the other
  25 (the players and a few bosses/NPCs) are rejected by the Python tool. The
  C++ converter now also takes the player models (the four alternate outfits),
  whose unreached extra meshes the Python tool does not skip, so those four have
  no Python reference. The Tick and Zombie Wesker output is the file play-tested
  in the game (2026-09-28).
- The Saturn arenas (`saturn`) against `tools/saturn_room.py rdt`: same
  length, and the only differing bytes are the transparency relabel's TIM
  indices (65,062 texels over 6 rooms).
